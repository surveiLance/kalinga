# Offline School Workflow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Teachers can prepare Kalinga online, close it, reopen on their own device without signal, teach with saved lessons/materials, record attendance and later sync to the same account.

**Architecture:** Add a production-only, build-inventoried service worker to the existing Next.js app. Keep scoped classroom localStorage and its durable queue, introduce an explicit local-only access state, and store selected PDF snapshots transactionally in scoped IndexedDB records. Keep offline availability distinct from cloud authentication and sync status.

**Tech Stack:** Existing Next.js 16.2.6/Turbopack, React 19, TypeScript, Supabase browser client, Vitest; browser Service Worker/Cache Storage/IndexedDB APIs. Add `pdfjs-dist` for a self-hosted offline PDF renderer, `fake-indexeddb` for transactional tests, and `@playwright/test` for isolated production-browser acceptance. Check compatible current package versions and lock them in package-lock; no runtime CDN.

**Spec:** `docs/superpowers/specs/2026-10-27-offline-school-workflow-design.md` (approved 27 October 2026).

## Global Constraints

- Preserve `app/page.tsx` view-state navigation and surrounding dense code style; no broad refactor, new state library or build-system switch.
- Use `workspaceStorageKey(scope, key)` and its extended key union; never merge teacher/prototype data or flush A's queue under B.
- First-ever preparation requires internet; offline AI, new guest enrollment/re-entry, uploads and community posting are not included.
- Preserve queue IDs, capped retries, delete tombstones, pending-local-wins reconciliation and attendance's `learner_id,attendance_date` identity.
- Never cache authentication callbacks/tokens, Supabase/API responses, private classroom records or signed URLs in the global worker cache.
- PDF downloads are explicit, scoped snapshots, limited to 20 MiB per file; no ready claim before bytes and metadata commit.
- Sign-out locks local access without deleting pending work; cached auth events cannot undo that lock. No authentication bypass or copied credentials.
- No real learner data or credentials in fixtures, logs or screenshots; no live DB/security changes anticipated.
- Keep generated output and unrelated untracked media out of commits. Verify and push each finished unit to main; do not expose incomplete readiness.

## Review Focus

1. Captive portal or network flag still online: bound network work, preserve the eligible local workspace, and never confuse a timeout with account revocation. Task 3 tests this.
2. Delayed SIGNED_IN/TOKEN_REFRESHED after explicit sign-out or account switch: do not unlock/queue under the stale account. Task 3 tests cross-tab locks and async epochs.
3. Signed URL expires, download is removed elsewhere, or account changes mid-transfer: a late completion must not restore removed/foreign resources. Task 2 tests transactional operation tokens and scope cancellation.
4. New deployment while an unsaved lesson is open: old shell remains usable, no forced reload, and mixed-build pages do not report prepared. Task 1 tests inventory/build matching and worker lifecycle.
5. Cold offline Word/PDF use: lazy export/renderer/worker assets must be cached before their first interaction. Tasks 1 and 5 check those actual imports and rendering.

### Task 2: Durable scoped PDF downloads

**Files:** Create `lib/offline-resources.ts`, `components/offline-pdf-viewer.tsx`, `tests/offline-resources.test.ts`, `tests/offline-pdf-viewer.test.ts`; extend `lib/workspace-keys.ts` and its legacy exclusion type. `LibraryResource` integration is in Task 4, not this unit.

**Interfaces:** Export `OfflineResourceInfo` with stable id, source, optional storagePath/ownerId, title, subject, grades, description, tags, author, visibility, type and pages; no signed URL. Export `OfflineResource = {version:1; scope:string; info:OfflineResourceInfo; blob:Blob; size:number; downloadedAt:number}`. Async `listOfflineResources(scope):Promise<OfflineResource[]>`, `getOfflineResource(scope,id):Promise<OfflineResource|undefined>`, `removeOfflineResource(scope,id):Promise<void>`, and `downloadOfflineResource(scope, info, url, {signal, isCurrent, onProgress}):Promise<OfflineResource>` store actual bytes. `onProgress` receives `{received:number,total?:number}`; `isCurrent():boolean` prevents stale-scope commits. Viewer props `{blob:Blob; title:string}`.

- [ ] Add failing IndexedDB tests with `fake-indexeddb`: same ID in A/B/prototype stays separate; reopening restores bytes+metadata; rollback keeps old good copy; quota/abort/empty/non-PDF/truncated/>20MiB streams never become downloaded; missing content-length is still bounded; URLs/tokens never persist; remove in another tab or account change invalidates late completion.
- [ ] Run `npm test -- tests/offline-resources.test.ts tests/offline-pdf-viewer.test.ts` and confirm red.
- [ ] Implement a versioned IDB store with `[scope,id]` keys and an operation-generation store. Starting/removing a download updates its generation transactionally; final blob+metadata commit checks generation and `isCurrent()`. Keep old bytes until successful replacement. Downloads have an AbortController and 60-second upper bound, validate MIME/PDF header and received length, and stream-cap at `20 * 1024 * 1024`. Reject unsupported scopes. Publish only scope/id change events via BroadcastChannel with a scoped localStorage fallback key, never PDF bytes or credentials. Persistence requests are best effort; blocked IDB reports actionable failure without clearing other storage.
- [ ] Implement a client-only lazy PDF.js viewer that receives local bytes, uses self-hosted worker/resources and never a remote viewer. Render one page at a time with labelled previous/next controls, page count, bounded canvas scaling and readable failure fallback to a local blob-open link. Cancel/destroy superseded render/document tasks and revoke URLs on scope/unmount/removal. Add an accessible page-text alternative from PDF.js text content rather than a canvas-only success claim.
- [ ] Test transactions and viewer cleanup; full tests/lint/build. Confirm Task 1 inventory includes newly emitted viewer code/worker. Commit/push these dormant modules without changing online library behavior.
